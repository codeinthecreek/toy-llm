Token embeddings, projected to 2D, across five checkpoints

Same PCA treatment applied to the 65×64 token embedding matrix at steps 0, 2000, 4000, 6000 and 8000. Each checkpoint refits its own PCA basis, so absolute orientation isn't comparable step-to-step — what's worth reading is whether structure exists at all, and which tokens sit near which. Hover any point for its character.

Token class whitespace (\n, space) punctuation & digit letter (upper + lower)

Step 0 → no structure

At initialization every point sits in a tight blob within ±0.09 of the origin — random init, no learned relationships yet. There's no separation by token class because nothing has been learned.

Step 2000 → case split emerges fast

By the first checkpoint, uppercase letters (A–Z) have moved to the left half of the plot and lowercase letters (a–z) to the right, with whitespace sitting among the lowercase cluster. This is the single biggest structural change in the whole run, and it's mostly in place after just 2000 steps.

Steps 4000–8000 → the split sharpens, doesn't reorganize

The uppercase/lowercase axis persists essentially unchanged through the rest of training; what changes is magnitude — points drift further from the origin (e.g. $ and & push out to the far left-top), meaning the model is sharpening distinctions it already found rather than discovering new ones.

Punctuation stays loosely clustered

Punctuation and the lone digit 3 occupy a diffuse band between the two letter-case clusters throughout training — expected, since a 108K-param model over ~8K steps only has so much capacity to carve out fine-grained structure beyond the dominant case signal.
